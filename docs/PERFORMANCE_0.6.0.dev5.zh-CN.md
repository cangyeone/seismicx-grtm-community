# 三类正演/微分、设备边界和批量效率 — 0.6.0.dev5

[English](PERFORMANCE_0.6.0.dev5.md) | 简体中文

2026-10-21；源码/二进制版本 `44e0ef8`。只计算同机比值。速度比定义为基线耗时 / 新路径耗时，低于 1 表示更慢。
本报告不能证明反演结果或地下结构更准确。设备精度/计算边界见[接口指南](DEVICE_EXECUTION.zh-CN.md)，下载见[dev5](PREVIEW_0.6.0.dev5.zh-CN.md)。

本轮优化：CPU RF 原生正演和解析 VJP、CUDA RF 梯度临时量归约、CUDA Green 解析微分积分/收缩与缓冲区复用、Green 有序批量 backward、面波 CPU 模型×周期并行。
MPS 的 RF/面波为显式 CPU FP64 桥接；Green Metal 仍是混合算法。没有把兼容接口计作原生 GPU 加速。


## 方法与资源

Apple M4 Max，16 核、128 GiB；远程 Threadripper PRO 3955WX，16 核/32 线程，RTX 5090（卡 1，约32 GiB），WSL2，驱动576.88。
Torch 为 Apple 2.8.0 / CUDA 2.8.0+cu128。三类测量使用安装的源码构建 wheel；相同源码构建的编译发行 wheel 单独做实际硬件回归。
pyfk 比较使用原仓库未修改的 Cython 构建与同版本 GRTM 原生库/源码包装，Apple Python 3.9.6、远程3.8.10；其余为3.12/3.13。

每项先热身1次，再同步测3次，取中位数，原始重复完整保留。后端顺序固定，没有随机轮转，短调用会受系统抖动影响。
同一主机的本次测量任务串行运行，不停止其他用户任务。没有跨主机相除。
RF 两个 CPU 路径均4线程（Torch准备4线程）；面波CPU16线程；Green共16个主机线程，B>1 时4模型工作线程×4原生线程。
disba/pyfk 保持原始串行，不伪造多核版本。以下分别给出多核 GRTM 与原始串行库的比值。

## 数值一致性与限制

本轮 CUDA/CPU 对照最大相对范数差：rf: 2.876e-15; surface: 2.740e-09; green: 2.907e-09.

| disba B256 | Relative Δ from GRTM |
|---|---|
| 相速度 | 3.963e-07 |
| 群速度 | 6.598e-05 |
| 相速度 + 全层 Vs 核 | 1.944e-02 |
| 群速度 + 全层 Vs 核 | 2.275e-02 |


这些是本组模型/离散问题的一致性检查，不是普适误差上限。独立解析、差分校验、参数JVP/VJP对偶性、非默认CUDA设备/stream、MPS图连接和模型变化回归见验证记录。已有[严格面波数值审计](PERFORMANCE_0.6.0.dev4.zh-CN.md)保留；本轮没有修改物理方程或放宽根容差。
MPS输入/实输出float32会带来舍入；CPU FP64桥接不消除该边界。极端准静态结构梯度、高阶自动微分和未测试GPU架构没有额外保证。


发行二进制完整回归：Mac 111项，94通过/17跳过；CUDA 111项，100通过/11跳过。跳过项按平台或可选依赖区分。CPU、MPS、CUDA三套双语接口例子均执行成功。

文档的单模型 Green 微分实例记录 32 个 CUDA 频点、0 个 CPU 频点、8 个解析参数方向。该例未触发低频扩展精度保护；主机FFT/物理合成边界仍在，不能外推为所有模型都没有主机计算。
