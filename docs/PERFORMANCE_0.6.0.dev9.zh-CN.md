# dev9 格林函数显式积分核：精度与速度

新增 `vjp_method="wavefield"`，使用原有 GRTM 波场的闭式层内正向/伴随重叠积分，解析计算全部结构参数梯度。CPU/CUDA 使用相同公式，不增加深度积分节点，也不逐参数扰动传播。默认方法保持原样。

## 测量范围

以下来自实际安装的 dev9 二进制，源码版本 `f3d8106fc059ab75ba5580fbaa3fadcaeb908917`。同一个 wheel 内比较 `adjoint` 与 `wavefield`，每组模型、节点、目标函数和精度相同。模型使用 FP64，固定波数网格、PTAM=0，选取全部六列结构参数与震源梯度；有效结构参数数为 6L−1。batch 模型的速度逐个变化 0.1%。

预热 2 次、重复 3 次，报告同步墙钟中位数；原始数据保留每次计时。正演+VJP 包含传播、物理合成、FFT 与反向；VJP 列复用正演图，但两条原生梯度路径均需重建波场。CPU 原生线程数均为 4，Torch 线程数为 1；CUDA 低频 CPU 保护也使用这 4 个线程。

小网格为 N=16、K=32（8 个非负频率）；大网格为 N=128、K=512（64 个非负频率），K 是每个频率的波数步数。P=0 使用 dt=0.1 s、积分周期长度 1000 km，无受保护频率；P=3 使用 dt=0.4 s、500 km，大网格保留 3/64 个原有受保护频率。小网格使用 dt=0.4 s、500 km，P=0。不同 P 的大网格是不同任务，不能跨行当作算法提速。

共 144 条最终计时记录；模型梯度相对反向 AD 的最大范数误差为 **2.067e-14**。独立测试还覆盖全部 30 个原始通道、力源/矩张量、所有材料列、源/接收几何、应力/应变、非默认 stream、中心差分和 CPU/CUDA 一致性。这个误差衡量导数实现一致性，不代表波数网格已达到连续积分真值，也不证明反演一定更准确。

八个周期、Rayleigh 基阶、1 个 CPU 线程，固定相同 FP64 根。QEDispInv 的 `kernel(freq,c)` 接收已知相速度，这里不计寻根，也不计其 C++ map 封装开销；GRTM 也只计能量核。因此这不是完整频散正演或格林函数波数积分的直接速度对照。

QEDispInv 较快的原因包括专用实数 CPS 公式与较小的封装开销；其模型入口虽为 float32，内部主要运算却已是 double。只改输入为 double 并不能消除 `SNGL` 和默认精度常数的影响。本组完整提升输入、内部显式 float32、SNGL 和常数精度后，最大核差降到约 2.2e−13。此实验只覆盖这些基阶点，不保证截止附近高阶模的识别。

本次去掉 GRTM 相速度能量路径不使用的 Fc/Ft 预计算，32 层 B=32 提速约 1.54×。QEDispInv 原版专用核仍约快 2.06×；没有把其源码复制入求解器。群速度所需周期导数保持不变。

## CUDA 收益与限制

新实现把层模态与积分分配到 (频率,波数,层) 并行，正向/伴随求解按 (频率,波数) 并行，最后确定性规约，常规频率无需 AD tape。FFT、物理合成和常规梯度在同一 GPU。仍有两个限制：小任务的调用/同步成本，以及大时间窗中原有低频扩展精度 CPU 保护。保护阈值没有放宽。batch 仍逐模型调用，没有跨模型融合，不能把 B 增加本身描述为额外 GPU 提速。

显式核仅改变导数路径，原有正演仍占端到端时间；因此端到端不能直接套用仅 VJP 的加速比。计时使用三个样本，微秒级小任务会受系统噪声影响，结果不作跨硬件保证。未采用降低精度、减少节点或省略源/界面项的优化。

## 验证与证据

两个实际安装 wheel 各执行 143 项测试；Apple 117 通过/26 平台跳过，Linux/CUDA 134 通过/9 平台跳过。完整日志、包装审计和二进制哈希见发布验证目录。新增 CUDA 子进程退出测试验证 autograd 工作线程结束时不会再次调用已关闭的 runtime。

CPU 结果没有统一提速：M4 Max 端到端约 1.33–1.59×，Threadripper 约 0.79–1.16×，其中部分任务变慢。默认保留原方法，CPU 用户应按自身任务选择；不要把 GPU 的加速比推广到 CPU。
