# 面波正演与敏感核速度报告 — 0.6.0.dev3

2026-10-20；RTX 5090、Threadripper PRO 3955WX；FP64/complex128。
以下主表为 **32 层、12 周期（2–50 秒）、16 模型、Rayleigh 基阶**，时间单位为秒，均为完整批次。

## 纯 CPU：与原始 disba 0.7.0 比较

双方均为单线程。GRTM 使用半解析微分；disba 保留默认 Dunkin 算法，未修改、未加多线程。
预热后重复 3 次取中位数，表中“加速比”为 disba 耗时 / GRTM 耗时；小于 1 表示 GRTM 更慢。

| 任务 | 类型 | disba CPU (s) | GRTM CPU (s) | 加速比 |
|---|---|---:|---:|---:|
| dispersion | phase | 0.042797 | 3.303400 | 0.0130× |
| dispersion | group | 0.084155 | 3.459268 | 0.0243× |
| sensitivity | phase | 7.486630 | 4.128910 | 1.8132× |
| sensitivity | group | 14.863389 | 9.367613 | 1.5867× |

纯 CPU 的完整 Vs 核分别加速约 **1.81 倍、1.59 倍**。纯频散目前没有提速：相速度约慢 77 倍、群速度约慢 41 倍。
本实现逐周期扫描完整自适应速度网格；disba 根据前一周期/模态结果缩小寻根范围。
两者采用各自默认设置，寻根精度没有强制匹配：GRTM 根容差 1e-10 km/s，disba 默认 dc=.005；
disba 群速度使用默认 dt=.025 的频率差分，GRTM 使用解析周期导数。
纯频散结果不能用敏感核的加速比替代。

## CUDA：只计算频散，不计算核

预热后重复 5 次取中位数；GPU 同步计时。复用对象的常态调用包含完整寻根；
“完整调用”另含从主机速度模型开始的对象构造、模型搬运和网格准备。

| 类型 | disba CPU (s) | CUDA 常态调用 (s) | CPU/CUDA | CUDA 完整调用 (s) | 完整调用 CPU/CUDA |
|---|---:|---:|---:|---:|---:|
| phase | 0.043280 | 0.225457 | 0.1920× | 0.257796 | 0.1642× |
| group | 0.086314 | 0.258540 | 0.3339× | 0.303097 | 0.2758× |

当前 CUDA 纯频散仍慢于 disba CPU。固定为同一套 GRTM 数学实现后，CUDA 相对 GRTM CPU 的常态调用加速如下：

| 类型 | GRTM CPU (s) | GRTM CUDA (s) | 加速比 |
|---|---:|---:|---:|
| phase | 3.133448 | 0.222995 | 14.05× |
| group | 3.373608 | 0.256063 | 13.17× |

## 与完整敏感核结果的关系

此前正式 CMake 库的独立批次复测中，完整相速度/群速度 Vs 核的 CUDA 相对 disba CPU 加速为 **27.4× / 41.1×**；
固定同一 GRTM 数学实现时为 **16.0× / 27.6×**。原始时间和重复值保留在随附 JSON。
这些数据与上面的纯 CPU 补测属于不同批次，不混合相除来构造新的加速比。

GPU 和主机均为共享硬件，未停止其他任务。结果只描述本次模型、默认设置和硬件负载；没有将数值核精度或运行时间推断为地质反演准确率。
频散测试中相速度与 disba 最大差约 2.44e-6 km/s；群速度差包含 disba 默认频率差分误差。
